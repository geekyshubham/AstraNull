# Surface hierarchy and color emphasis — brand decision

2026-10-04. **Pending decision.** DESIGN.md requires pure-black dark canvas/cards/raised surfaces. This document does not change that rule. It defines two controlled candidates for a later authorized design comparison.

## Candidate A — current identity

Canvas, ordinary and raised dark surfaces remain #000000. Reduce outline weight through fewer nested panels, whitespace, flat observation rows and hierarchy. Keep existing border tokens/wash; one meaningful orange CTA. A remains the compatible default.

## Candidate B — one raised tone

Keep black canvas and ordinary work areas. Propose one restrained raised tone for dialogs, evidence overlays and the selected inspector: reference swatch #101214, subject to formal token/contrast review. Do not spread charcoal to every metric/table/card, create more layers, or change orange/brand marks.

This is a Markdown proposal, not a shipped token. If selected later, update shared DESIGN.md/tokens intentionally. A with better composition may prove sufficient.

## Comparison

Render R1 dashboard, R2 profile and R4 evidence overlay using identical data, type, space and motion disabled. Compare A/B in dark and light; light keeps existing white/tinted hierarchy.

Evaluate active inspector visibility, readability without tracing borders, selection under color-vision variation, actual contrast of text/focus/icons/dividers/charts, and primary-action discoverability. Record chosen option, rationale, approved artifact/version and scope in [reference register](11-reference-screen-specifications.md). Individual page agents cannot decide independently.

## Emphasis

| Role | Treatment |
| --- | --- |
| Orange | Primary task action and meaningful selection, not every link/provider card. |
| Green | Measured success in stated scope; detection is not automatically green assurance. |
| Amber | Needs review/gate uncertainty; unknown also needs text and neutral clarity. |
| Red | Recorded important failure/gap or deliberate danger action. |
| Neutral | Attribution, unknown/unmeasured, technical metadata and chart context. |

One obvious primary per task region. Header and active dialog can each have one because focus contexts differ; do not make every row orange.

Large charts use restrained semantic fills and legible values; saturated success is a small marker. A green ring cannot overpower open high-priority gaps. Any lower-chroma chart token is also a shared decision; do not silently change --success for every badge to quiet one donut. Unknown/stale remain visible; no gradient, glass, glow or color-only states.

## Status

A is the current default. B and chart-tone changes await explicit design decision. Data contracts, reference specifications and task hierarchy can progress without pretending the theme choice is approved.
