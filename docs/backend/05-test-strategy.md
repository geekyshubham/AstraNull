# Backend and Platform Test Strategy

## Local Node test execution

`npm test`, `npm run test:unit`, and the corresponding Make targets run one Node test file at a time. The suite includes wall-clock performance budgets; launching a worker for every reported CPU can make unrelated test files compete with those measurements. File-level serialization preserves the existing performance thresholds and all assertions. Tests for races still create their explicit parallel requests and Postgres transactions inside each test.

The browser suite remains a separate command: `ASTRANULL_PORTAL_SCALE=1 npm run test:portal-playwright`. Run it separately from Node performance measurements when collecting final verification evidence.

HTTP fixtures whose clients use `127.0.0.1` must explicitly bind IPv4 loopback, await the listening callback before reading `server.address()`, reject startup errors and await the shared `closeServer` cleanup. Follow `tests/integration/waf-summary.test.mjs` and `tests/integration/verification-ladder.test.mjs`, including their address/family regressions. On Darwin, an IPv6 wildcard listener can share a port with an unrelated IPv4 listener, so an IPv4 client can reach that other service. The verification-ladder failure log records all five requests reaching the owned PostgreSQL IPv4 port 61947; owned two-listener HTTP reproduction confirms the misrouting mechanism, and a no-request bind confirms a wildcard HTTP listener can coexist on that PostgreSQL port. Awaited cleanup is resource hygiene, not the cause of this routing repair. The vector-library follow-up reproduces the first unauthenticated request failing before any fixture connection, including a wildcard ephemeral port equal to the owned PostgreSQL IPv4 port. An owned IPv4 socket-closing sentinel and same-port wildcard HTTP listener reproduce `UND_ERR_SOCKET`, 188 request bytes, zero response bytes and zero intended-server requests on Darwin/Node 26. Both vector API fixtures explicitly bind IPv4 and assert their address/family; the second fixture's listening and assertions stay inside its cleanup-protected block. This establishes the reproduced mechanism, not direct trace attribution of the original uninstrumented Make incident or every historical socket/status failure. Keep existing endpoint, count, authorization and error assertions unchanged.

Timestamp-change assertions must control the event clock rather than assume successive HTTP requests cross a millisecond boundary. The repeated WAF finding-finalize integration test uses a test-context-scoped, Date-only mock and advances exactly 1 ms before the second update. It retains finding identity, last-validation-run, timestamp-change and audit assertions, and requires the exact new timestamp. Real timers, production timestamps, authorization and evidence freshness bounds remain unchanged. Its shared HTTP fixture also follows the awaited explicit-IPv4 startup/cleanup contract above.

## Service-layer rate limits

Unit tests cover fixed-window reset, per-client key separation, and production fail-closed when `ASTRANULL_RATE_LIMIT_DISABLED=1`. Integration tests use a low `ASTRANULL_RATE_LIMIT_MAX_REQUESTS` on a dedicated server instance so the default operability server is unaffected. Gateway/WAF limits are documented as required production defense-in-depth but are not simulated in CI.
