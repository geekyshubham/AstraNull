# ADR-0026: First reviewed safe execution lifecycle

Date: 2026-10-10

Status: Proposed, implementation stopped by user on 2026-10-11; interrupted source is unaccepted and must remain unavailable. No reviewed runtime enablement is delivered.

## Context

[ADR-0023](0023-reviewed-inert-operation-preflight.md) binds passive customer review and current exact material authority. [ADR-0025](0025-durable-reviewed-grant-issuance.md) addresses durable independent signing, with local acceptance still in progress. Neither supplies a reachable reviewed admission/reservation/worker/result lifecycle. A valid signature or an internal issued replay must not become another execution opportunity.

The next slice must be complete across that lifecycle before removing any current reviewed runtime denial. It must not expand rejected cloud/read-only integrations, SOC workflows, customer agents/environments, discovery, unmanaged traffic or reusable attack recipes. Existing high-scale SOC gates remain mandatory.

## Proposed bounded first scope

Use only the existing safe `waf.evasion_base64_wrap.safe` GET query comparison at an active customer-declared exact URL with current direct DNS-v2 proof and assurance-v3 material. Require the existing exact `marker-query-v1` human review. Preserve the catalog profile and fixed inert marker serializer; reject caller profiles, markers, bodies, headers, endpoints and callbacks. No implicit method/path/body expansion is permitted.

A comparison contains a separate actual permitted GET, an untransformed fixed inert marker GET, and a transformed fixed inert marker GET. Reserve at most three probe operations plus the existing two hostname destination-resolver attempts, with one execution attempt, no retry/refund and the unchanged original maximum 120-second authority, clamped by review/collection/safe-window bounds. Stop after an unhealthy permitted leg; incomplete or contradictory observations stay inconclusive. Transport must pin the exact reviewed origin and path and prevent redirects or alternate destinations.

This scope can demonstrate only the existing bounded inert-marker scenario. Original nonce-hash-bound custody is not a target nonce echo. It does not supply nonce-echo origin receipt, origin lockdown, hidden-layer attribution, CVE mitigation, inspection/resource resilience or DDoS capacity. Those claims require separate explicitly reviewed producer contracts and actual evidence, not a broader interpretation of this result.

## Required lifecycle

1. **Admission:** signed-worker mode only; retain existing permission, active target/group, subscription, complete rate/cooldown/concurrency accounting, and kill-switch gates. Safe windows, rate caps and cooldowns are recorded on the audit trail but never refuse; only the subscription allowance can defer. Build current authority under the same managed audit-first safe-start transaction. Store its immutable run snapshot and include the exact reviewed binding and ownership in the original job before its first HMAC signature. No simulation success or caller override.
2. **Recovery:** compare stored authority, original profile and clocks; never construct replacement proof, add/remove a selector, renew a deadline or duplicate a run job. A consumed reservation/signing opportunity is not repairable into a new execution opportunity.
3. **Reservation:** add a distinct reviewed branch, leaving ordinary reservation SQL guards intact. Authenticate the existing worker-ID/method/path/timestamp/raw-body/tenant request signature. Under audit/run/kill-switch/current-authority locks, authenticate the original HMAC and exact active job/run/lease, current material/review/direct proof and fresh time. Durably reserve the entire allowance once with typed reviewed identity before any destination I/O.
4. **Grant:** issue against that actual stored reservation using the independently signed committed ledger. Never add the later reservation/grant to original signed constraints or re-sign the original job. A worker-facing execution response must require a newly issued opportunity; internal identical issued replays remain non-executable diagnostics and cannot be converted into retry permission. Lost-response outcomes remain consumed.
5. **Worker:** verify the actual original HMAC, strict original reviewed binding and independent active purpose-pinned Ed25519 grant against exact tenant/job/worker/lease/reservation/budgets/deadlines before all destination DNS/socket/HTTP. Then atomically and durably consume a tenant/job/reservation execution claim before I/O, across every reviewed entry including direct execution. Fresh-only grant delivery alone cannot stop a received grant being reused by concurrent handlers, retained responses or process restarts. An in-memory set is insufficient. All processes sharing a signed worker identity require the same durable uniqueness boundary; unavailable storage or an unsupported deployment topology must deny execution. Crash/cancellation/uncertainty after claiming never frees the claim. Mutable `authorized` or `signedJobVerified` booleans cannot replace signature or durable-consumption checks. The reviewed branch uses only the fixed safe producer and existing counted/pinned transport, without changing ordinary behavior.
6. **Evidence:** record typed actual per-leg role/order/request descriptors, immutable observation/completion clocks and original job/nonce-hash/reservation/grant lineage. Reconstruct accepted authority on the server; reserve new authority metadata against worker spoofing. Use a versioned reviewed receipt rather than rewriting historical `accepted-probe-execution.v1` semantics. Partial/unknown capture never becomes a pass.
7. **Replay/Stop:** reconcile duplicate ingestion only from the durable accepted event; reject fresh positive evidence from pending jobs or new stale holders. Preserve Stop requested/acknowledged/unreachable distinctions, fail-closed reporter behavior and conservative accounting. No database status is packet-cessation proof.

The preferred shared consumption boundary is server-backed through the existing authenticated worker control plane and tenant PostgreSQL store, not new database/cloud credentials distributed to workers. Every reviewed entry must actually obtain a fresh committed claim before destination I/O; cached authorization booleans or a received grant cannot bypass it. Claim uniqueness is the original tenant/job/run/reservation identity, not a caller-generated request nonce. Request/response binding and commit-acknowledgement failure tests must prevent a retained response from masquerading as a fresh claim. This architecture is still proposed, not an implemented guarantee.

Dev remains unavailable unless equivalent durable uniqueness/current-authority semantics are provided. Startup must fail closed for partially configured dedicated grant trust/signing dependencies; there is no custody-secret or ordinary-authorization fallback. No live signer is constructed or contacted during local tests.

## Acceptance before enablement

An actual local application-role test must cover admission, original signed job, reviewed reservation, injected real Ed25519 signing, bounded loopback three-leg producer, accepted custody and immutable result replay. Use injected/pinned local resolver transport, not public targets. Add concurrent admission/revocation, exact definition/proof/profile drift, original deadline recovery, duplicate job/lease/poll/restart/lost-response denial, uncertain reservation/signing outcomes, invalid dual signatures with zero destination I/O, unhealthy baseline, partial comparison and stale-holder rejection.

Only after the entire slice and affected/broad regressions pass may the specific reviewed runtime branch be enabled. A helper's passing tests, seeded reservation, generic marker response or metadata validator is insufficient. Current reviewed runtime deny guards remain mandatory until then. Production migrations, deployment, live signer/probe availability and real human/operational acceptance require separate current authorization and genuine evidence.
