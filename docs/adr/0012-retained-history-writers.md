# ADR-0012: Retained history writers

## Status

Accepted (2026-10-04). Extends the foundation in migration `0064` and the read model in ADR-0011. Does not change ADR-0008: verdicts stay outside-in, and a binding is not an executor.

## Context

The history tables existed, and the signed-result writer still replaced `target_edge_detections` in place. Run version, producer, and expected behavior were not stamped. A request body could have been treated as those values. A newer transport failure could have been stored as a fresh negative. Finding closure had a column and no audited lifecycle.

## Decision

1. **Stamps come from the catalog and the approved runtime.** `deriveRunEvidenceStamp` sets `check_version`, `scenario_version`, `producer_kind`, `expected_behavior_json`, and `provenance_json` when a run is created. Body fields `version`, `check_version`, `scenario_version`, `producer_kind`, `live`, and `expected_behavior` are ignored. The digest keeps request and body pattern semantics and replaces credential values with `[redacted]` before hashing. The returned object does not echo those values. An explicit catalog `version` wins. Old rows with a null `check_version` stay partial.
2. **Producer kind is the path that actually ran.** Signed-worker egress of a non-ops check is `signed_probe`. Inline simulation is `internal_simulation`. An ops-readiness check stays `customer_declaration` even when the dispatch mode is `signed-worker`, because that check does not leave the host. Inline probe events stay `internal_simulation`. `customer_declaration` is not written onto probe events.
3. **Expected behavior is the catalog default at start.** It is stored on the run. Later reads do not substitute today's `target.expected_behavior`. A catalog check with no default stores null. The writer does not invent `must_block_before_origin`.
4. **Signed edge history and the current row move in one tenant transaction.** `recordProbeResultEdgeDetection` appends accepted observations on the ingest client, then upserts. A Postgres `BEFORE UPDATE` trigger keeps the current edge row from moving backward. The trigger orders by `observed_at`, then `test_run_id`. The edge table has no `source_completed_at`. A row whose `observed_at` is null remains a legacy overwrite so existing unstamped upserts still apply. A null observation does not clobber a stamped row. Replay does not insert a second observation. A late nonce does not replace a newer current row. A different family's latest failure stays on its own pointer. Timeout, TLS, DNS, and transport errors append `failed_attempt` and do not upsert a negative or remove the last success.
5. **Origin history requires the authorized binding.** An approved `host_sni_bypass` result records `origin_hosting` only when `require_binding` matches an active binding whose origin target is the observation target. A mismatch skips that origin write. Edge fingerprint history does not borrow the binding id. `validateHostSniTargetBinding` is unchanged.
6. **Run start checks the binding before insert.** `origin_binding_id` requires the run target to be that origin, an approved origin check, the same host, SNI, port, and path derived from the protected declaration, and current proof for both targets. Proof uses `effectiveTargetVerifications` and `ownershipProofFromStates`. A raw `provider_verified` row whose connector is revoked or disabled is not proof. Create still requires origin proof only. The body cannot add `direct_ip`, a discovered destination, or another executor.
7. **Retest intent is explicit and per finding.** `retest_of_finding_id` requires `finding:write` plus the same tenant, target, and check. Postgres inserts `finding_retest_lineage` in the same transaction as the run, before dispatch. A later run of the same pair without that row stays `later_same_pair`. Nothing closes the finding or a sibling. `can_advance_remediation` stays false.
8. **`closed_at` is an authorized closure timestamp.** `planFindingPatch` accepts `open`, `in_progress`, `accepted_risk`, `resolved`, `closed`, `false_positive`, and `accepted`. Closure statuses set `closed_at` once. `open` and `in_progress` clear it. The repository writes `closed_at` only when the patch includes it, and keeps an existing timestamp. The audit action remains `finding.updated`. The record does not say a fix was proved.
9. **Profile fields are additive.** `historyReadModel` attaches retained family state, confirmed comparable changes, and origin bindings after `deriveProtectionProfile`. A confirmed change is the adjacent pair of the two newest successful observations of one family. A version change is a gap, not an improvement. Recorded provider identity is the safe provider string only: a same-versions provider change is an explicit `provider_changed` entry, never an improvement or a loss, and a missing provider is a gap only for outcomes whose vendor is the substance (same `detected`); the same generic outcome (pass/fail), the same bound reachable/unreachable origin result, and the same `not_detected` absence stay behavior comparable without a provider. `comparison_gaps` serialize onto the profile and coverage, next to the comparable changes. Origin assurance is an exact active binding plus a finalized bound observation. Unbound IP reachability does not become assurance.
10. **A rebinding is never a silent replay.** Creating the same active protected/origin pair replays only the identical host, SNI, port, and path. A different requested scope for that pair is `409 scope_conflict` in both stores; an exact identical scope replays without a mutation or traffic.

## Consequences

Dev JSON and Postgres start paths both stamp the run. The Postgres probe-result adapter and the dev `recordSignedProbeHistory` hook both append history. Target detail and the portal detail bundle attach the read model. The portal bundle reads the newest 100 observations and active bindings, and loads proof only when a binding row exists. That adds two sequential reads, or three when a binding exists.

`server.mjs` is unchanged. `POST /v1/test-runs` already forwards the body and maps `result.error`, so `retest_of_finding_id` and `origin_binding_id` are live on that route and body version flags are ignored. `GET /v1/findings/:id` returns the service object, which now includes `closed_at`, `lineage`, `retests`, `originating`, and `latest`. `PATCH /v1/findings/:id` still returns 200 unless the controller checks `if (result?.error) return json(res, result.status, result)`. An invalid lifecycle is not persisted.

Read-only scan methods, for the next controller pass: `getValidationScan(ctx, id, { advance: false })`, `getValidationScanActivity(ctx, id, { advance: false })`, `dispatchDueValidationScans(ctx, { advance: false })`, `advanceScan(ctx, id, { advance: false })`. `listValidationScans` has no advance path. The current scan GET passes only `runtimeConfig`, so a pending scan GET still advances. There is no observation HTTP route. A later route must not copy `internal` from the body.

`db/schema.sql` and `PROGRESS.md` are outside this slice. Migration `0063` is not rewritten.
