# ADR-0034: Missing-control findings, check efficacy matrix and remediation assistant

Date: 2026-10-17
Status: Decisions 1–3 accepted and implemented locally; decisions 4–5 deferred (not implemented in this phase). Staging/operational acceptance remains separate.

## Context

AstraNull's purpose is to tell a customer what is missing in their environment. Findings did not do that: 196 of 275 checks carried boilerplate remediation ("Review edge protection for this vector."), finding titles read `Finding: <verdict> on <target>`, and no check mapped to a provider control (GCP VPC firewall / Cloud Armor, AWS security groups / NACLs / AWS WAF / Shield, Azure NSG / Front Door WAF / DDoS Protection, Cloudflare, Akamai), although edge/cloud provider detection already exists (`targetEdgeDetectionStore`). Detection efficacy was also unproven: only 14 checks exercise both a control-present and a control-missing scenario through the signed lifecycle, and 76 network checks are observation-only and can never raise a finding.

## Decision

1. **Missing-control contract.** Every catalog check has an entry in `src/contracts/missingControls/` naming its `control_family`, the `missing_control` (what the customer's environment lacks when the check flags a gap) and the `required_policy` (the policy they need). Generic text is rejected by tests. `GET /v1/findings/:id` projects a `missing_control` object built from this entry, the finding's recorded evidence statement and provider guidance; `/v1/checks` and `/v1/checks/:id` carry the static entry. The stored finding title is unchanged because ADR-0009 rule/alert grouping keys on it; the projection's `headline` (`Missing control: <family label>`) is what the portal shows first. Verdict explanations name the evidence precisely: the managed-rule attack class, every declared-deny port that answered (most sensitive first), the leaking AXFR nameservers and the evasion transform versus the blocked plain marker.
2. **Provider guidance, not attribution.** `src/contracts/providerRemediation.mjs` maps each control family to provider-specific controls, steps and official documentation for `gcp`, `aws`, `azure`, `cloudflare`, `akamai`, `fastly` and `generic`. Guidance is ordered by the target's detected edge/cloud layers and labelled with its detection source and layer. It is advice for the detected provider; it does not establish which control failed (`attribution: 'unattributed'` and `control_identified: false` are unchanged).
3. **Observation-only upgrades where inferable.** An observation-only check is upgraded to gap-capable only when external evidence alone proves a missing control without a customer declaration. Upgrades key on check id, apply only after the existing correlation concludes `inconclusive` (declared-deny, WAF and probe-failure outcomes keep precedence), and require attested probe I/O with no evidence gap or probe failure. Implemented: never-public services (Telnet, SMB, Docker API, etcd, Redis, Elasticsearch, kubelet, MongoDB) completing a handshake from a non-CDN peer while another scanned port is closed/rejected/filtered (`nfw.management_port_exposure.safe`, `l3.firewall_exposure_scan.safe`); two agreeing Redis handshakes (`reflect.redis_direct_exposure.safe`); expired or not-yet-valid certificates (`tls.full_audit.safe`); a single delegated nameserver (`dns.secondary_failover.safe`); AstraNull's foreign Origin reflected with credentials (`l7.cors_posture.safe`); confirmed unauthenticated gRPC reflection (`protocol.grpc_reflection_stream.safe`); no advertised HTTP/2 stream limit (`protocol.http2_stream_concurrency.safe`); and a client-initiated renegotiation accepted on TLS 1.2 (`tls.renegotiation.readiness`, one in-band attempt on the existing connection, gated to that check id, no cap change). Possibly-intended public ports (SSH, RDP, SQL, VNC, Kubernetes API, LDAP), hostname mismatch and private chains stay observations. Not implemented: legacy TLS handshake, DNS TCP fallback and IPv6 parity sampling (each changes signed request caps or the check's delivery definition, which needs a governed recipe change); XML-RPC identity (requests a path other than the signed target URL); origin lockdown without `lockdown_expected` (needs edge detection in both runtimes' correlation inputs); owned-zone open recursion (needs an AstraNull-owned canary zone that does not exist yet). Every implemented upgrade has control-missing, control-present and guard tests.
4. **Isolated efficacy matrix (deferred).** Owned in-process loopback peers gain explicit control-present and control-missing behaviours, and a container fault lab (`tests/fixtures/connect-fault-lab/`, network `none`, only `NET_ADMIN`/`NET_RAW`) proves SYN-drop timeouts with an exact-tuple kernel drop rule and its counter. For every verdict-capable check the matrix asserts: control missing → gap verdict, finding, and a missing-control statement; control present → no finding. No external host, public target or third-party vulnerable application is contacted.
5. **Remediation assistant (deferred).** A finding-grounded assistant, modelled on the CheckRed DNSPM chat (status endpoint, background chat jobs polled by the UI, untrusted-data wrapping, secret redaction, per-user/per-tenant rate limits), uses the local Antigravity CLI (`agy`) through a stream-JSON adapter in plan mode with its sandbox, in an empty per-job workspace, with open web search. The complete finding is sent after secret redaction. The adapter never passes `--dangerously-skip-permissions`, and it kills the run if any tool other than `search_web` or `read_url_content` starts. It is default-off: it needs a deployment flag and per-tenant opt-in, and it is read-only advice that never changes verdicts, findings or readiness.

## Deferred work

Decisions 4 and 5 are recorded design intent only; no fixture behaviours, kernel-drop receipts, assistant endpoints or `agy` integration were implemented in this phase. A container image definition (`tests/fixtures/connect-fault-lab/Dockerfile`, pinned base plus `iptables`/`tcpdump`/`iproute2`) and a manual feasibility run showed an exact client/server-tuple `DROP` rule counts only its own SYNs and times out the connect while an unrelated tuple still connects; this is not accepted coverage and the nine SYN-timeout branch obligations remain open.

## Boundaries

The `agy` adapter needs the CLI installed and signed in on the host that runs the control plane; it is a local/single-operator integration, not a hosted multi-tenant model gateway. Web results are untrusted and the assistant's answer is advisory. Provider guidance and assistant answers can be wrong or stale; customers verify them against their provider. Efficacy results are local engineering evidence, not live production acceptance.
